# Paired inference protocol v1

L40S comparative evaluation is deferred following the hardware NO-GO. See the [milestone status](README.md) and [preserved worker runbook](LIVE.md).

The primary comparison measures the effect of attaching the final AxonAI-v1 LoRA adapter to the pinned bare base. Both arms use the same text-only loading route on the same reserved pair of 48 GB L40S GPUs. Model placement spans both GPUs for each generation. The 80 pairs require 160 scheduled responses. The historical checkpoint run produced no observations for this comparison.

## Frozen generation policy

The custodian registers the protocol, software build, model inventories, neutral system message, signed pilot roster, generation profile, seed, block assignment and explicit GPU placement map before releasing pilot jobs. The model host captures and signs independent observations of the following settings. Its launch attestation includes the private ticket-to-identity binding. The scheduler receives opaque tickets and completion states. An opaque identifier or a digest alone supplies no access control.

1. Use identical immutable offline images with pinned Python, PyTorch + CUDA, Transformers, tokenizers, Accelerate, PEFT, safetensors, attention kernels, native libraries and driver. Record the resolved package versions, image digest and driver/build flags. The published packaging environment is a starting manifest. Record the two physical L40S UUIDs in order, memory, SM version, free memory, exclusivity, clock/power policy and device visibility. Reject CPU/disk offload, extra visible devices, busy devices and runtime drift. Derive an explicit common base-module to device map on a benign preflight. Freeze its bytes and verify actual module placements after each load. Assign adapter tensors to their target layer's device. [Recorded dependencies](../../../models/merged/AxonAI-v1-27B/DEPENDENCIES.json)
2. Load the pinned text path with local files only, remote code disabled, `AutoModelForCausalLM`, BF16 base weights, SDPA with the math backend pinned, `eval()`, disabled gradients and inference mode. Start a fresh process per block. Enforce the observed `Qwen3_5ForCausalLM` class, expected text parameter count (26,895,998,464), BF16 base-storage/dtype whitelist, base placement and vetted loader key report. The original source includes non-text parameters. Freeze the exact expected discarded-key inventory against a reviewed local-only preflight and reject any added missing, unexpected or mismatched keys. Arm A must contain zero adapter modules. In B, independently compare all 992 loaded original LoRA tensors with file values as in the packaging harness, verify active and enabled adapter, verify base parameters have identical shapes, placements and values, and disable merge and training. Freeze that evidence before decoding.
3. Set both arms to the same BF16 autocast compute policy. Preserve the original adapter file and verified load precision, including any PEFT FP32 master weights. Freeze the actual base/adapter parameter and compute dtypes and required model FP32 state exceptions. Validate the LoRA matmul compute dtype under autocast with a synthetic control. Tensor dtype and compute dtype answer different questions. Set TF32 off, cuDNN benchmarking off, deterministic algorithms with errors enabled, fixed cuBLAS workspace and hash seed before worker startup, fixed RNG seed 42 per item, and the same allowed optional-kernel inventory. Pin PyTorch SDPA kernel selection on each block. Repeat the benign control through a fresh load with matching IDs and output token sequence in each arm. A determinism failure pauses the run for a new reviewed freeze.
4. Use the base tokenizer for both slots. Render once using `render_item`, explicit system and user messages, generation prompt on, thinking off, no truncation, no padding and no second special-token insertion. The private renderer binds the full UTF-8 bytes, tokenizer/template/version, ID sequence, count and item ID. Persist that sequence with restricted access. Both workers consume these exact IDs. Preserve the same all-ones mask and zero-based positions under the validated batch-one path. Hash each worker's actual device-bound IDs before generation and compare with the rendered input commitment. An overflow gets a paired `context_overflow` receipt, including when only a single input token exceeds the 4,096 total. The common 384-token output allowance leaves 3,712 input tokens.
5. Use greedy batch-one decoding, single beam, seed 42, 384 maximum new tokens, identical cache policy, no repetition penalty beyond 1, no custom stop strings or length penalties, explicit tokenizer BOS/PAD and a common ordered EOS set from the pinned config. Freeze the full resolved generation configuration, including disabled sampling, inherited processors, renderer source and detokenization settings. Decode only the continuation with special tokens skipped and token-space cleanup disabled. Fail on a nonfinite raw logit. Stop immediately at the first permitted EOS or the common cap. Treat EOS on the final allowed step as a normal stop. Keep complete outputs for scoring even when capped. Output-token counts include any generated terminal EOS. The profile in `runner.py` binds the prospective settings to every row.

## Private worker and receipt interfaces

`runner.py` implements one-time rendering, artifact inventory checks, runtime and input parity checks, per-item outcomes and roster reconciliation. Its Python interface takes an observed `Runtime` and a `decode(input_ids, max_new_tokens) -> Decode` callback. The live backend implements this callback. Only disposable CPU mocks have run. Before a pilot, deploy the load/decoder process and validate it against the read-only, model-host-controlled artifact manifest. The common runtime digest binds the image, resolved software lock, actual placement, kernel configuration and physical GPU pair. The renderer digest includes the pinned tokenizer and source hash. Independently record and validate concrete preimages for every digest and authenticate the worker signing key. A callback that merely echoes a requested input digest would defeat the input check.

- In custody, bind the signed run manifest to immutable approved worker/runner hashes, dataset freeze, two independently authenticated opaque worker tickets and the exact committed model checks. The model operator sees only its assigned local model and signed request. The inferencing scheduler cannot access model mounts, host diagnostics, worker role bindings, scoring stores or review aliases. Limit its telemetry to progress. Use per-job authenticated transport and put control-plane and data-plane services under different principals. The kernel's local SHA-256 checks detect accidental drift inside this trust boundary. Actual mount ACLs, authenticated receipts and their cross-service verification are infrastructure deliverables.
- Balance first-slot position within task family as closely as counts permit by assigned, recorded private randomization. Use `pilot.paired_blocks` with an independent private order seed to assign the 80 pairs to two equal, family-balanced blocks. Hash-lock the order, use a separately randomized ticket-to-artifact mapping and retain the same within-block item order for both loads. Run the first block in ticket order XY and the second in YX. Each block phase uses a fresh load with identical synthetic warm-up. Freeze order and timeout policy before any real output. Record load, checksum and warm-up separately from generation. This design has four loads. It controls first/second position and makes block effects visible.
- Measure monotonic prefill-through-final-token latency with synchronized GPUs. Record synchronized time to first chosen token, raw output IDs, total token count, each GPU's reset peak allocated/reserved bytes and process peak host RSS (Linux KiB converted to bytes). Record wall start/end timestamps, physical device health, free memory, bytes read, and peak device memory at load in a separate sealed worker log. Throughput is generated tokens divided by generation seconds. Report prefill-inclusive and decode-only rates separately, excluding decode-only cases with fewer than two tokens or zero post-first-token time.
- Persist results atomically in a private append-only store. Select only one primary attempt per frozen run/slot/item. A worker failure retains the row with its typed cause. `empty_output` preserves emitted IDs, elapsed time and the empty visible text. The separate `stop_reason` distinguishes EOS and output cap even on a blank continuation. Score this returned response as zero with the empty-answer classification. `context_overflow`, `oom`, `timeout`, `nonfinite_logits`, `backend_error` and `worker_lost` have missing output fields. Missing resource measurements remain null. A separate supervisor must attest timeout, signal or crash from the assignment ledger, release device reservations and record a terminal failure even if the process dies before emitting a receipt. A worker integrity error halts the affected freeze. An unexpected exception pauses for diagnosis. Freeze any rerun as an explicit linked sensitivity run. Never silently replace a failed output with a later success.
- The custodian verifies authenticated receipt envelopes, worker/model bindings and both registered tickets, then calls `audit_pairs` against the original schedule. It rejects missing/extra items, duplicate slots, input mismatch, inconsistent stopping, metric corruption and runtime or runner drift. Audit with the identical frozen runner bytes. The custodian stores raw rows privately and creates separate independently relabelled reviewer exports. Only after ratings freeze, convert `measurement.latency_s`, `first_token_s`, peaks, `input_tokens`, `output_tokens`, `status` and sealed score links into the analysis input. Retain zero-output failures in denominators.

## L40S capacity estimate

Reserve both 48 GB L40S GPUs together, preferably 128 GB host RAM for a conservative margin. A published BF16 packaging baseline on two L40S (base + adapter) recorded process peak RSS 53,682,500 KiB and allocator peaks of 25.55 and 30.16 GB. Its weight-placement allowance was 38 GiB/device. These are observations for the shorter packaging workload. Budget for the larger prompt/cache peak at 3,712 + 384. The manifest covers 55,586,047,268 bytes of base files and 467,048,935 bytes of final adapter files, about 52.2 GiB together. Use a pre-existing read-only copy or reserve at least that much model storage plus private job artifacts and image space. Validate max-envelope memory, capacity and latency on approved synthetic controls before starting the roster. [Resource receipt](../../../models/merged/AxonAI-v1-27B/VALIDATION_SUMMARY.json) · [Placement documentation](../../../models/merged/AxonAI-v1-27B/README.md)

For planning only, the transferred 12-pair Stage 0 report recorded about 11.36 base and 9.06 adapter generated tokens/s. Its 1,986 and 1,134 total tokens imply 165.5 and 94.5 mean output tokens. The short uncontrolled workload and the stricter prospective deterministic backend limit prediction. Compute generation seconds as `80 × mean_base_tokens / base_tps + 80 × mean_adapter_tokens / adapter_tps`. Charge both GPUs for the entire wall reservation.

| Output-length assumption | Generation wall | Wall with overhead and contingency | GPU-hours |
| --- | ---: | ---: | ---: |
| Stage 0 means, 80 pairs | 0.56 h | 1.32–1.95 h | 2.6–3.9 |
| Both arms reach 384 every time | 1.69 h | 2.74–3.37 h | 5.5–6.7 |

These scenarios add an assumed 0.5–1.0 wall hour for verification, four loads, warm-ups, staging and I/O, then multiply by 1.25. Request an initial four-hour window (eight GPU-hours) conditional on operator approval and synthetic measurements. Longer prefills, kernel changes, contention or slower cold storage can exceed it. Reforecast from family-stratified pilot input/output lengths, latency quantiles, throughput and failure rates, retaining phase-specific overhead. Human review, replication and confirmatory runs require separate budgets.

## Replication and release gates

Include the pinned bare comparator for the paired scientific endpoint if testing the release contrast. On V100, freeze a separate matched FP16 base and adapter comparison on the same reserved V100 devices with a validated precision/placement policy, then evaluate the FP16 release in its own replication. Live work requires the independent identity custodian, signed runtime/receipt service, model worker integration, tested durable private sink and watchdog, approved pilot input release, GPU reservation and a fresh operator authorization. Evaluate signed mount/ACL enforcement, watchdog recovery, actual input tensor attestation, full-context fit, parity and reproducibility on approved synthetic controls first.
