# Scoring and paired analysis · v1

## Private scoring contract

Before sampling, the author and an independent subject expert freeze the answer contract, private key, support material, rubric, reference implementation or test suite, applicable error codes and pass threshold for each revision. Both models receive the same format instructions, option catalog, unit vocabulary and approved evidence. Keys and per-response records live in the restricted scoring store. The scorer takes the exact visible generated suffix after locked decoding. Store the original output, parsed score, independent ratings, adjudication and final score as separately versioned records bound to the response commitment.

`score.validate_key(key)` checks rule data before release. `score.score(key, response, verified_sandbox_receipt=...)` returns `status`, binary `pass` (or null) and a list of hard-error codes. The closed contracts require one complete JSON object with unique keys, case-sensitive IDs, no markdown wrapper and only the declared fields. A contract violation yields `format_error`. Preserve it separately from a valid-format scientific error. A delivered empty answer receives zero with `empty_answer`. An answer delivered at the output cap is scored as delivered and flagged for truncation. Hardware, custody and scoring-service failures remain unscored. A malformed private rule stops scoring pending custodian review.

| Kind | Private fields in addition to `kind` | Visible answer and pass rule |
|---|---|---|
| `multiple_choice` | `options` (array), `answer_id` | One `answer_id` matching the key. Invalid options and wrong listed options have distinct labels. |
| `numeric` | `targets` maps each permitted unit to a decimal-string `value` and `atol`. `rtol` is a nonnegative decimal string. | `value` and `unit`. Compare exact rational values in the submitted unit. Accept absolute error ≤ max(atol, rtol × abs(target)). Specify target and tolerance for each approved conversion. Use the unit ID `1` for dimensionless quantities. |
| `evidence` | `answer_id`, `source_ids`, `required`, `support` | One `answer_id` plus `claims`, an array of objects with `id` and `sources`. Require the correct answer and every required claim. The source-ID set for each submitted claim must match one approved complete evidence set in `support[claim_id]`. |
| `citation` | `source_ids`, `required`, `support` | `claims` only. Detect missing required claims, claims absent from the support table, missing citations, IDs outside the supplied snapshot, and citations that fail to support the cited claim. Closed source IDs denote specific passages/table entries. |
| `abstention` | `answer_ids`, `reason_ids`, exactly one populated | `decision="answer"` with an accepted `answer_id`, or `decision="abstain"` with an accepted `reason_id` on an unanswerable case. Count unnecessary abstention and failure to abstain separately. Balance answerable and unanswerable cases in the four-item family, then report counts by opportunity. |
| `programming` | `suite_sha256`, `profile_sha256`, `tests_total` | Raw program in the requested language and interface. Match the authenticated private receipt to SHA-256 of the raw UTF-8 response, locked suite and execution profile. Require all hidden tests to pass within limits. Report candidate errors, resource exhaustion and infrastructure errors separately. |
| `expert` | Rubric stored separately under the rule reference | Free response with a pending primary score until independent review and any adjudication are complete. |

A structured evidence item assesses a fixed inventory of claims and evidence. For open scientific writing, expert reviewers identify each material factual claim, locate the supplied passage or independently verify the frozen citation record and its entailment, and log the evidence in their rationale. Distinguish a citation that was unresolved in the frozen evidence, a verified nonexistent identifier, a real source with incorrect metadata, an irrelevant source and an unsupported inference. Predeclare whether external citation verification by a separate rights-cleared custodian is needed. Preserve unresolved verification as unscored when it determines the pass decision. Report response-level error prevalence and, when a manual claim audit was prespecified, report unsupported claims over all audited material claims. The automated counts in `analysis.py` use responses as their unit.

Use numeric or choice scoring for checkable biomedical facts, statistical quantities and general-retention answers. Require a locked reasoning rubric for biomedical multistep reasoning and experimental design. It should specify the inferential steps, evidentiary support, assumptions, controls, confounders and interpretation required by that item. Specify essential criteria separately from optional details. Transfer items use the same scoring contract as their task type. Restrict pilot content to benign, rights-cleared tasks suitable for the evaluation environment.

## Blinded review and final score

Assign two independent domain-qualified reviewers, calibrate against disposable development examples, freeze the anchors, and give each reviewer their individually shuffled single-response packets. Use the reviewer's authenticated account for submission. Keep reviewers' identities, assignments and credentials in the custodian vault. Reviewers provide an ordinal rating, fatal-error flag and supporting rationale before seeing another rating. Archive the two signed or access-controlled submissions with timestamps and packet commitments. Any AI-assisted annotations require a separate diagnostic record and have zero weight in the human endpoint.

| Rating | Required interpretation |
|---:|---|
| 0 | The answer misses the central task or contains a fatal scientific error defined by the rubric. |
| 1 | Some relevant work appears, but at least one essential criterion fails. |
| 2 | All essential criteria are met. Minor nonfatal defects may remain. |
| 3 | All essential criteria are met, with sound justification and no material defect. |

Review for scientific validity independently of verbosity. Where possible, split similar prompts across review sessions, randomize response order, and record suspected identity leakage privately. If disclosure compromises masking, quarantine the affected packet and version any replacement workflow. A distinct authorized specialist resolves differences in rating or fatal-error flag using the frozen evidence and anonymized rationales, with a separate timestamped decision. Unresolved cases keep a null score. Record agreement from the original two ratings even after dispute resolution.

`final_score(objective, dual_review=..., final_rating=...)` requires all applicable objective criteria and, when specified, a final expert rating of at least 2. A known hard objective failure fixes the endpoint at zero even while a required reviewer decision is pending. An objective pass awaiting required approval and an unresolved expert-only answer keep a null score. Track every assigned review independently of whether the binary endpoint is already known. The custodian supplies the final rating from the independent-review lock. For an invalid item or materially ambiguous key, preserve the original scores, log the decision for both arms while blind, report the paired exclusion and missing-score bounds, and move the revision to development diagnostics. An author may propose a revised diagnostic item after lock.

## Programming execution gate

The scoring library only consumes a separately authenticated execution verdict. Receipt digests bind bytes and config. Authenticate the producer and run/item assignment in the private job envelope before calling the scorer. The execution service requires approval and a tested isolation boundary. Its operator must demonstrate denied network egress including DNS, no credentials or host sockets, no model or key mounts, an unprivileged disposable worker, read-only runtime, bounded scratch, CPU time, wall time, memory, process count, output size and filesystem limits. Freeze language, runtime image, packages, platform, test seeds, test tolerances, interface and permitted libraries. The trusted supervisor owns the hidden tests and decides the verdict outside the candidate process. Destroy scratch after each response and retain only approved private receipts and bounded logs. Verify isolation with benign controls and reference solutions before accepting generated code.

A trusted receipt supplies `response_sha256`, `suite_sha256`, `profile_sha256`, `tests_passed` and `outcome` (`completed`, `resource_limit`, `candidate_error`, `infra_error`). The effective profile must include all approved limits. Candidate timeout or resource-limit exceedance under a validated profile counts as failure. An executor outage yields a null score. A missing sandbox leaves nonempty programs pending. No execution service is activated by this protocol.

## Analysis contract

After final score lock, the custodian maps opaque tickets to A and B in the restricted analysis environment. `analysis.analyze(roster, results)` takes the entire frozen roster including unsuccessful jobs. Translate item-registry fields `task_family` and `source_family_id` to `family` and `source_family` alongside `item_id`. Carry the locked `answerability` value on every `uncertainty_abstention` item. Supply at most one result per scheduled item and arm with `item_id`, `arm`, `status`, `pass`, `errors` and optional `new_tokens`, `latency_s`, `truncated`. Missing rows are retained. Status values are `scored`, `inference_failure`, `scoring_error`, `sandbox_unavailable` and `pending_review`. Preserve each exact inference failure reason in `errors`. Keep failed-attempt timings in execution receipts for cost accounting. Publish only cleared aggregate tables, suppressing small or identifying cells as required.

- **Primary pilot summary.** Count adapter-only pass W, base-only pass L, both-pass ties and both-fail ties on jointly scorable pairs. Report denominators, per-arm pass rates among scored responses and paired difference (W−L)/complete. Report the prespecified quota-weighted mixture as the item mean on the completed design, along with counts in every task family. Missing pairs can change family weights in the complete-case estimate.
- **Missingness.** For the assigned-roster difference, compute the sharp lower and upper bounds by setting each missing B score to 0 or 1 and each missing A score to 1 or 0, retaining every observed score. Report operational failure and missingness separately per arm. Interpret the complete-case comparison conditionally when coverage differs. For a completeness gate failure, the report remains diagnostic.
- **Precision.** The library gives a conservative 95% paired interval, clipped at −1 and 1. For jointly scored source-family clusters of sizes m, half-width is sqrt(2 log(40) × sum(m²)) / complete. This follows from applying Hoeffding's inequality to independent bounded cluster sums, with arbitrary dependence within a cluster. Its sampling interpretation requires independent source-family draws and a defensible selection/missingness model. A hand-constructed diagnostic frame supports only conditional design summaries. Sparse task-family intervals are descriptive. No selection of favorable endpoints, families or model checkpoints after observing outputs. [Hoeffding, 1963](https://doi.org/10.1080/01621459.1963.10500830)
- **Review.** Join both original ratings on the custodian's opaque response handle with stable reviewer order. `agreement(pairs, levels=4)` reports assigned and double-rated counts, the confusion table, exact agreement, Cohen's κ and linearly weighted κ. Also run on pass/fail labels with `int(rating >= 2)` and two levels, retaining each missing rating as null. Use null for incomplete ratings and undefined κ from homogeneous margins. Report results per fixed reviewer pair and rubric where assignments differ. Keep adjudication rates, fatal-error disagreements, unresolved cases and reviewer time as separate workflow measures.
- **Abstention opportunities.** The `abstention_opportunities` report gives per-arm unnecessary abstentions on answerable items and failures to abstain on insufficient-evidence items. It reports interpretable decisions, invalid/empty answers, unscored assignments, and the event rate among interpretable decisions. All-assigned rate bounds allow every unresolved decision to be either outcome. A correct decision with an incorrect reason still contributes to the decision-rate denominator and fails the full item.
- **Errors and efficiency.** Report scored error-label counts over scored responses, operational failures over allocated arm slots, and the number with known truncation. Multiple labels may apply. Count generated suffix tokens with the frozen stop-token convention. Compare matched counts, per-arm mean, median, nearest-rank p95 and paired B−A values for response length and synchronized generation latency. Calculate pooled output tokens / pooled generation seconds on the same matched timing cohort. Include model load, warm-up, retry time, peak per-device memory and reviewer time separately for budget calculations. Keep all resource outcomes separate from correctness.

## Planning the next study

Choose a scientifically meaningful absolute difference δ with an independent scientific lead before arm-labeled pilot outcomes become accessible. Use pooled pilot discordance and a conservative upper bound q. The library sets every incomplete pair discordant for this bound and adds the one-sided 95% independent-cluster Hoeffding margin using the entire assigned roster. Examine a prespecified sensitivity grid, changes in population mix, reviewer reliability and the uncertainty in the failure rate. For a new target population, obtain new design assumptions.

`plan_pairs(q, δ, alpha=.05, power=.8, attrition=...)` uses the paired normal approximation with a two-sided threshold. Required complete independent pairs are ceil((z(1−α/2)√q + z(power)√(q−δ²))²/δ²). Enrollment is ceil(complete / (1−attrition)). Use feasible q ≥ δ. The following scenarios assume 10% attrition and one independent source family per pair. [Connor, 1987](https://pubmed.ncbi.nlm.nih.gov/3567305/)

| Assumed q | Target difference | Complete pairs | Enroll |
|---:|---:|---:|---:|
| 0.20 | 0.10 | 155 | 173 |
| 0.40 | 0.10 | 312 | 347 |
| 0.20 | 0.05 | 626 | 696 |
| 0.40 | 0.05 | 1,254 | 1,394 |

Replace scenario inputs with blinded pilot estimates after the pilot. Have a statistician verify exact unconditional power for the planned paired test or simulate the locked stratified/clustered design, attrition and multiplicity. Approximation error can matter at low discordance. Preregister the target population, sample size, direction, estimand, single primary test, margins and missing-data sensitivity before independent holdout authoring and release.

For N scheduled pairs, project two generations per pair using pilot arm-specific time distributions and a conservative contingency based on observed retry, startup and outage time. Convert two-device wall-hours to GPU-hours by multiplying by two. For R responses requiring human judgment, estimate 2 × R × mean independent rating minutes / 60 reviewer-hours, plus R × dispute fraction × mean adjudication minutes / 60 specialist-hours. Add item writing, rights review, screening, calibration, sandbox evaluation and secure custody as separate line items. Report ranges from observed pilot time variation. Record benchmark cost, reviewer agreement and throughput even when the direction of the paired capability estimate is unfavorable.
